# تطبيق لعبة المسابقات المحلية: «سؤال جواب»

تطبيق أندرويد أصلي (Kotlin + Jetpack Compose) للعبة مسابقات محلية تنافسية لأربعة لاعبين على شبكة Wi-Fi المحلية نفسها، مع نظام بوزير (Buzzer) عالي الدقة، إدارة التوقيت والتحكيم، وعجلة اختيار السائل الدائرية، مع الحفاظ التام على البنية التحتية للبناء وCI/CD للمشروع.

---

## مراجعة المستخدم والقرارات الحاسمة (User Review & Critical Decisions)

> [!IMPORTANT]
> تم تثبيت الخيارات الأساسية بناءً على إجابات الاستيضاح والتحليل المعماري:
> 1. **اكتشاف الغرفة**: اعتماد البث التلقائي عبر الشبكة المحلية (UDP Broadcast Discovery) مع إتاحة إدخال عنوان IP ومنفذ المضيف يدوياً كخيار بديل موثوق.
> 2. **منظومة التغذية الحسية والمرئية**:
>    - **الفائز بالبوزير**: نغمة انتصار قصيرة + اهتزاز واضح + توهج أخضر ناعم على حواف الشاشة (Green Edge Glow) يظهر ويتلاشى بتدرج أنيق عدة مرات.
>    - **الخاسرون**: توهج أحمر ناعم على حواف الشاشة للإشارة الفورية لقفل البوزير.
>    - **السائل (المضيف)**: نغمة تنبيه هادئة فور حسم المنافسة.
>    - **المجيب المنقول إليه**: نغمة مختلفة ونمط اهتزاز خاص عند نقل الصلاحية عشوائياً.
>    - **التحكيم**: نغمة إيجابية للإجابة الصحيحة، ونغمة خطأ للإجابة الخاطئة، مع مراعاة وضع الصامت وإمكانية تعطيل الصوت/الاهتزاز من الإعدادات.
> 3. **عجلة السائل التالي**: عجلة دائرية دوارة كلاسيكية ناعمة تعرض أسماء اللاعبين الأربعة مع مؤشر توقف عشوائي صادر من المضيف.

---

## 1. نظرة عامة والمفهوم الأساسي (Overview & Core Concept)

- **ماذا يفعل التطبيق**: يدير جلسة مسابقة محلية لأربعة لاعبين دون الحاجة إلى إنترنت أو خادم خارجي أو إنشاء حسابات. الهاتف المضيف (Host) ينشئ خادم Ktor WebSocket محلي وبث اكتشاف UDP، وتنضم الهواتف الثلاثة الأخرى عبر Ktor WebSocket Client.
- **طبيعة الأسئلة**: الأسئلة تُطرح وتُجاب **شفهياً في العالم الحقيقي**. دور التطبيق هو ضبط التنافس على سرعة الضغط، إدارة مؤقت الإجابة، تمكين السائل من التحكيم (صحيح/خطأ)، تدوير الأدوار تلقائياً، واحتساب النقاط.
- **الجمهور المستهدف**: الأصدقاء والعائلات في الجلسات المشتركة، بأسلوب تنافسي سلس وواجهة داكنة مريحة باللغة العربية (RTL).

## 2. تجربة المستخدم والتصميم البصري (User Experience & Visual Design)

### المسار العام للمستخدم (User Flow)
```
[شاشة البداية] ───┬──> [إنشاء غرفة] ──> (بث الخادم + انتظار 4 لاعبين) ──┐
                 └──> [انضمام لغرفة] ──> (اكتشاف تلقائي / إدخال IP)  ──┴──> [اكتمال اللاعبين]
                                                                                   │
┌─────────────────────────── [شاشة اختيار السائل بالعجلة] <────────────────────────┘
│
├──> هاتف السائل: [تحديد الصعوبة والمدة] ──> [بدء السؤال]
│
└──> هواتف المنافسين الثلاثة: [شاشة المنافسة: زر البوزير الكبير]
            │ (أول ضغطة مسجلة بدقة النانوثانية على المضيف)
            ├──> الفائز: [توهج أخضر + صوت + شاشة الإجابة ومؤقت تنازلي + زر "تم الجواب"]
            └──> الخاسرون: [توهج أحمر + شاشة انتظار مع إظهار اسم الفائز]
                        │
                        ▼ (الضغط على "تم الجواب" أو انتهاء الوقت)
            هاتف السائل: [أزرار التحكيم: "صحيح" / "خطأ"]
                        ├──> "صحيح": نقاط للمجيب ──> [شاشة النتيجة] ──> [العجلة للسائل التالي]
                        └──> "خطأ" أو نفاد الوقت:
                                ├──> لا نقاط للمجيب ويُستبعد من المحاولة الحالية
                                ├──> اختيار عشوائي ذري لمجيب جديد من المتبقين بمؤقت كامل
                                └──> إذا فشل الثلاثة: نقاط السؤال للسائل ──> [العجلة]
```

### الهوية البصرية والمظهر (Design Tokens & Visual Identity)
- **النمط**: Dark Minimalist، ألوان داكنة عميقة تخفف استهلاك البطارية وتبرز التفاعل التنافسي:
  - الخلفية الرئيسية: `#0F1115` (Jet Black).
  - بطاقات المحتوى: `#181B22` مع حدود ناعمة `#262B35`.
  - لون البوزير والحالة النشطة: ذهبي دافئ `#E5A93C` أو فيروزي متألق `#38BDF8`.
  - لون الفوز والتوهج الصحيح: زمردي `#22C55E`.
  - لون الخسارة والخطأ: قرمزي ناعم `#EF4444`.
- **الطباعة ودعم العربية**: دعم كامل لاتجاه RTL، أرقام عربية وخط واضح بنسب مريحة للقراءة عن بُعد.
- **التوهج الطرفي (Lightweight Edge Glow)**: مكوّن Compose مرسوم عبر `drawWithContent` متدرج على حواف الشاشة مع `Animatable` ناعم بدون تحميل أي صور ثقيلة أو التأثير على الأداء.

## 3. القرارات التقنية ومعمارية النظام (Technical Architecture)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        هاتف المضيف (HOST DEVICE)                       │
│                                                                        │
│  ┌──────────────────────┐      ┌────────────────────────────────────┐  │
│  │   UI (Jetpack Compose)│ <──> │ RoomViewModel                      │  │
│  └──────────────────────┘      └────────────────────────────────────┘  │
│                                                   │                    │
│                                                   ▼                    │
│                                ┌────────────────────────────────────┐  │
│                                │ GameManager (Authority)            │  │
│                                │ - StateMachine                     │  │
│                                │ - Mutex & Nanosecond Clock Lock   │  │
│                                │ - Score & Player Registry          │  │
│                                └────────────────────────────────────┘  │
│                                                   │                    │
│                                                   ▼                    │
│  ┌──────────────────────┐      ┌────────────────────────────────────┐  │
│  │ DiscoveryBroadcaster │      │ Embedded Ktor Server (CIO)         │  │
│  │ (UDP Beacon: 8888)   │      │ WebSocket Service (Port: 8080)     │  │
│  └──────────────────────┘      └────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────────┘
                                    ▲
                                    │ Wi-Fi LAN (WebSockets)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                      أجهزة اللاعبين (CLIENT DEVICES)                    │
│                                                                        │
│  ┌──────────────────────┐      ┌────────────────────────────────────┐  │
│  │   UI (Jetpack Compose)│ <──> │ ClientViewModel                    │  │
│  └──────────────────────┘      └────────────────────────────────────┘  │
│                                                   │                    │
│  ┌──────────────────────┐                         ▼                    │
│  │ DiscoveryListener    │      ┌────────────────────────────────────┐  │
│  │ (UDP Listener)       │ ───> │ Ktor WebSocket Client              │  │
│  └──────────────────────┘      └────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────────┘
```

### تفاصيل المكونات التقنية
1. **بروتوكول الشبكة والاتصال**:
   - حزم البيانات بنظام Kotlin Serialization (`@Serializable sealed class GamePacket`).
   - خادم Ktor مدمج خفيف الوزن (`io.ktor:ktor-server-cio` + `ktor-server-websockets`) يعمل في خلفية هاتف المضيف.
   - عميل Ktor (`io.ktor:ktor-client-cio` + `ktor-client-websockets`) على هواتف العملاء وهاتف المضيف (كمشغل محلي).
2. **خوارزمية حسم البوزير (Nanosecond Buzzer Lock)**:
   - استخدام `Mutex` غير قابل للتداخل في المضيف.
   - قياس زمن استقبال البوزير باستخدام `SystemClock.elapsedRealtimeNanos()`.
   - أول حدث يصل أثناء حالة `BUZZER_OPEN` يغير الحالة ذرياً إلى `ANSWER_ASSIGNED`، ويتم رفض أي أحداث لاحقة فوراً.
3. **التغذية الصوتية والاهتزاز**:
   - استخدام `ToneGenerator` مدمج أو `SoundPool` خفيف جداً لنغمات نظيفة وسريعة بدون تأخير.
   - `Vibrator` / `VibratorManager` لأنماط اهتزاز فورية مميزة للفائز والمنقول إليه.
4. **حالة عدم الاتصال (Disconnection & Recovery)**:
   - مراقبة نبضات القلب (Ping/Pong) كل ثانيتين.
   - في حال خروج لاعب يتم عزله من المحاولة الحالية، واستمرار اللعبة بسلاسة مع دعم إعادة المزامنة في حال عودته.

## 4. خطة التنفيذ المنهجية (Implementation Steps)

### المرحلة الأولى: تنظيف التطبيق القديم وفحص البناء
1. **فحص البنية الحالية والـ CI/CD**:
   - التحقق من ملفات Gradle وGitHub Actions (`.github/workflows/android-build.yml`) والتأكد من الحفاظ عليها تماماً.
   - تحديث `strings.xml` باسم «سؤال جواب»، وتحديث `metadata.json` مع الحفاظ على القدرات الأساسية.
2. **حذف كود وموارد zaidTV القديمة**:
   - حذف مجلدات `com.example.data.model`, `com.example.data.network`, `com.example.ui.components` الخاصة بـ TV Remote وScreen Mirroring.
   - حذف الصور والأيقونات القديمة الخاصة بـ zaidTV.

### المرحلة الثانية: إعداد الشبكة ومكتبات Ktor
1. إضافة اعتماديات Ktor الخفيفة وKotlin Serialization إلى `libs.versions.toml` و`app/build.gradle.kts`.
2. إنشاء نماذج البيانات وحزم بروتوكول اللعبة:
   - `Player`, `GameState`, `QuestionDifficulty`, `QuestionDuration`.
   - `GamePacket`: `JoinRequest`, `JoinResponse`, `BuzzerPress`, `BuzzerWon`, `AnswerDone`, `JudgeAction`, `StateSync`, `Heartbeat`.
3. إنشاء `UdpDiscoveryManager` للبث والاستماع على الشبكة المحلية (Port 8888).
4. إنشاء `GameServerManager` (خادم Ktor WebSocket) و`GameClientManager`.

### المرحلة الثالثة: منطق اللعبة ومحرك الحالات (Game Engine & State Machine)
1. إنشاء `GameEngine` على المضيف:
   - إدارة حالات اللعبة الكاملة وقواعد النقاط:
     - سهل: نقطة واحدة (كل المدد متاحة).
     - متوسط: نقطتان (كل المدد متاحة).
     - صعب: 3 نقاط (المدة دقيقة واحدة ممنوعة برمجياً وواجهات).
   - قفل البوزير بدقة النانوثانية.
   - نقل صلاحية الإجابة عشوائياً عند الخطأ أو انتهاء المؤقت.
   - احتساب نقاط السؤال للسائل عند فشل المنافسين الثلاثة.
   - اختيار السائل التالي عشوائياً بواسطة المضيف مع إمكانية تكرار السائل السابق.

### المرحلة الرابعة: التغذية الحسية والمؤثرات (Feedback & Effects)
1. إنشاء `FeedbackController`:
   - تشغيل النغمات الصوتية (فوز، خسارة، تنبيه السائل، نقل الإجابة، صح، خطأ).
   - تشغيل أنماط الاهتزاز مع احترام إعدادات المستخدم.
2. إنشاء مكوّن `EdgeGlowModifier` في Jetpack Compose (توهج أخضر للفائز، وتوهج أحمر للخاسرين بتلاشٍ انسيابي).

### المرحلة الخامسة: بناء واجهات المستخدم (11 شاشة متكاملة)
1. `HomeScreen`: البداية (إنشاء غرفة، انضمام، إعدادات الصوت والاهتزاز).
2. `HostLobbyScreen`: عرض اسم المضيف، رمز الغرفة، IP، وقائمة المنضمين (حتى 4).
3. `JoinScreen`: البحث التلقائي أو إدخال IP والاسم.
4. `QuestionSetupScreen`: شاشة السائل لتحديد الصعوبة والمدة وبدء السؤال.
5. `BuzzerCompetitionScreen`: زر البوزير الكبير للمنافسين مع مؤشرات الفوز والخسارة والتوهج.
6. `AnsweringScreen`: شاشة المجيب الحالي مع العداد التنازلي وزر «تم الجواب».
7. `JudgingScreen`: شاشة السائل مع زري «صحيح» و«خطأ».
8. `RoundResultScreen`: إعلان الفائز والنقاط المكتسبة ولوحة الترتيب.
9. `WheelScreen`: عجلة الاختيار العشوائية الدائرية الناعمة لاختيار السائل التالي.
10. `ScoreboardSheet`: لوحة النقاط المتاحة في أي وقت أثناء اللعب.
11. `ConnectionStatusOverlay`: إشعار فوري بحالة الاتصال واستعادة المزامنة.

### المرحلة السادسة: الاختبارات والتحقق النهائي
1. كتابة اختبارات وحدة محلية (Robolectric / JUnit) لقواعد اللعبة والتنافس بالنانوثانية والانتقال بين الحالات.
2. تشغيل `compile_applet` للتأكد من نجاح بناء المشروع وإنتاج APK سليم.
